# FCS Staffing

Map, columns and table views of the Foreign Commercial Service overseas footprint, a "who's where" mode, and a rules-driven bid list for the yearly cycle.

All locations and staffing patterns come from the Sept 2023 staffing deck. **Every person in the data is fictional.**

## Run

```bash
npm install
npm run dev
```

With no Supabase variables set, the app runs on generated mock data (`src/lib/seed.ts`) and keeps rules and bids in the browser.

## Layout

- `src/data/posts.ts`: posts, coordinates, hardship, language, staffing pattern
- `src/lib/seed.ts`: deterministic generator for positions, officers and simulated bids
- `src/lib/rules.ts`: cycle status, bidder role, per-position eligibility, bid-list checks
- `src/lib/declutter.ts`: pushes overlapping post boxes apart on the map, with leader lines to the true location
- `src/components/`: map (Leaflet), columns, table + pivot, bidding, rules admin, detail panel
- `supabase/migrations/0001_init.sql`: schema with row-level security (viewer / bidder / admin)
- `supabase/seed.sql`: generated by `npm run seed:sql`

## Connecting Supabase

1. Create a project, run `supabase/migrations/0001_init.sql`, then `supabase/seed.sql`.
2. Copy `.env.example` to `.env.local` and fill in the URL and publishable key.
3. Reads require a signed-in user under the RLS policies; sign-in is the next step to build.

## Deploy

The app is a static site (`npm run build` writes plain files to `out/`). Every push to `main` rebuilds it and publishes it to GitHub Pages through `.github/workflows/pages.yml`.

Each visitor's bids, rounds and rule changes are saved in their own browser. Use "View as" to demo the officer and admin sides.
